# Discord RPG Bot — кредитная система и Аркейн Банк

Проект объединяет RPG-бота, кредитную систему гильдии торговцев и банковский реестр. Все реальные передачи алмазов происходят в Minecraft. Бот не перемещает предметы: сотрудники записывают операции только после проверки фактической передачи.

## Установка

1. Python 3.10 или новее.
2. Установите зависимости: `python -m pip install -r requirements.txt`.
3. Задайте переменную окружения `DISCORD_TOKEN`.
4. В Discord Developer Portal → Bot включите **Server Members Intent** и **Message Content Intent**. Остальные intents бот включает только по необходимости; события присутствия, набора текста и голосовых состояний отключены для снижения нагрузки.
5. Запустите `python main.py`.

Не храните токен в исходном коде. Если он когда-либо был опубликован, перевыпустите его в Discord Developer Portal.

## Кредитная система

- `.credit_help` — справка по кредитам.
- `.credit_apply СУММА 7|14|30` — подать заявку; нужна регистрация и подтверждённый паспорт.
- `.credit_status [@участник]` — проверить кредит.
- `.credit_requests` — список заявок для сотрудников торговцев.
- `.credit_approve ID` / `.credit_reject ID причина` — одобрить или отклонить заявку.
- `.credit_issue ID [примечание]` — подтвердить фактическую выдачу алмазов после одобрения. Только после этой команды запускаются проценты и график платежей; сумма выдачи списывается из свободной казны.
- `.credit_pay ID СУММА [примечание]` — подтвердить фактически полученный платёж. Поступление отражается в казне.
- `.credit_passport @участник да/нет` — проверить паспорт.
- `.credit_staff @участник да/нет` — назначить сотрудника кредитного отдела (только лидер торговцев).
- `.credit_edit ID ПОЛЕ ЗНАЧЕНИЕ причина` — исправить запись с аудитом (только лидер).
- `.credit_audit [количество]` — посмотреть аудит (только лидер).
- `.credit_service_channel #канал` — задать канал уведомлений (только лидер).
- `.credit_limits [срок минимум максимум]` — посмотреть или изменить базовые лимиты (только администратор; `0` означает отсутствие максимума).

Лимиты по умолчанию: 7 дней — 448–700 алмазов под целевые 10%; 14 дней — 896–3200 под 15%; 30 дней — от 4480 без фиксированного максимума под 20%. Ставка рассчитывается по оставшемуся основному долгу и полным 24-часовым интервалам. Все сроки используют `Europe/Moscow`.

## Накопительные счета

- `.savings_open topups` — открыть счёт с пополнениями, ставка 13% в месяц.
- `.savings_open no_topups` — открыть счёт без последующих пополнений, ставка 14% в месяц.
- `.savings_status [@участник]` — посмотреть баланс, ставку и состояние начисления.
- `.savings_deposit @участник СУММА [примечание]` — сотрудник записывает физически полученный взнос от 100 алмазов.
- `.savings_withdraw @участник СУММА [примечание]` — сотрудник записывает физическую выплату от 50 алмазов; остаток должен быть не меньше 100.
- `.savings_visit @участник` — сотрудник подтверждает посещение физического банка.

Режим ставки фиксируется при открытии. Каждое снятие снижает ставку на 0,2 процентного пункта, минимум до 5%. Проценты рассчитываются по периодам между операциями с учётом баланса и действующей ставки и капитализируются в конце календарного месяца. Проценты округляются вверх до целого алмаза при капитализации. Без подтверждённого посещения проценты не начисляются; после семи дней с последнего посещения начисление приостанавливается. Новое подтверждённое посещение возобновляет начисление с даты посещения без компенсации паузы.

Первоначальный взнос по счёту — не менее 100 алмазов. В режиме `no_topups` допускается первоначальный взнос, но последующие пополнения запрещены.

## Срочные вклады

- `.deposit_open @участник СУММА 14d|1m|1.5m|2m|3m` — сотрудник регистрирует физически полученный вклад от 500 до 5000 алмазов.
- `.deposit_status [@участник]` — посмотреть вклады.
- `.deposit_pay ID [примечание]` — подтвердить выплату по завершившемуся вкладу.
- `.deposit_early ID [примечание]` — досрочно закрыть вклад после физической выплаты.

Ставки за весь срок: 14 дней — 13%; 1 месяц — 13,5%; 1,5 месяца — 14%; 2 месяца — 14,5%; 3 месяца — 16%. Сроки календарные; для 1,5 месяца используется один календарный месяц плюс 15 дней. Если нужного числа нет в месяце, используется последний день месяца. Проценты при погашении округляются вверх до целого алмаза. При досрочном закрытии выплачивается 99% первоначального вклада (с округлением вниз до целого алмаза), проценты не выплачиваются.

## Казна и отчёты

- `.treasury` — сводка балансов и обязательств (сотрудники банка).
- `.treasury_add СУММА причина` — записать подтверждённое физическое поступление в свободную казну.
- `.treasury_expense СУММА причина` — создать запрос расхода.
- `.treasury_approve ID` — одобрить крупный расход (от 500 алмазов включительно) лидером торговцев.
- `.treasury_pay ID [примечание]` — записать расход после фактической выплаты.
- `.treasury_reserve СУММА причина` — перевести средства из казны в резерв.
- `.treasury_release СУММА причина` — вернуть средства из резерва в казну.
- `.bank_report week|month` — отчёт за последние 7 дней или текущий календарный месяц.
- `.bank_history [количество]` — последние операции.
- `.bank_staff @участник да/нет` — назначить/снять сотрудника банка (только лидер торговцев).
- `.bank_help` — полный список банковских команд.

Баланс свободной казны и резерв ведутся отдельно от средств вкладчиков. Средства клиентов не считаются свободными средствами банка. Выданные кредиты учитываются отдельно как задолженность заёмщиков. При выдаче кредита свободная казна уменьшается; подтверждённые погашения возвращают средства в казну. Проценты по накопительным счетам и срочным вкладам отражаются как расходы банка.

Расход от 500 алмазов требует подтверждения лидера. Для крупного расхода сначала создаётся запрос, затем лидер его одобряет, после физической выплаты сотрудник подтверждает `.treasury_pay ID`.


## Ограничение служебных команд Торговцев

- Служебные команды кредитного отдела и банка проверяют, что пользователь является участником Торговцев по регистрации или ранговой/лидерской роли, и что у него есть доступ сотрудника либо права главы.
- Выдавать доступ к кредитному отделу или банку можно только участнику гильдии Торговцев. Назначенный сотрудник, не состоящий в Торговцах, не сможет использовать служебные команды.
- Публичные команды клиентов (например, подача заявки или просмотр собственного счёта) остаются доступны по своим условиям. Администратор Discord сохраняет административный обход.

## Интерактивное меню и выполнение операций

- `.menu` (алиасы `.меню`, `.панель`) — единая точка входа. Разделы отображаются по членству и роли: личный кабинет, гильдия, квесты, СОБР, банк, кредиты и администрирование.
- СОБР-раздел не показывается тем, кто не состоит в СОБР. Разделы банка и кредитов показывают публичные действия клиентам, а служебные операции — сотрудникам/лидерам Торговцев. Внутри СОБР дополнительные действия фильтруются по рангу. Администратор Discord видит все разделы.
- В разделе выберите команду, прочитайте описание и нажмите «Выполнить через меню». Для действий с параметрами откроется форма. Значения передаются существующему обработчику, поэтому сохраняются штатные проверки доступа и бизнес-логика.
- Встроены подробные гайды для шахтёров, архитекторов, Торговцев (банк/кредиты) и СОБР. Их можно открыть кнопкой «Гайды гильдий»; администратор может открыть любой гайд.
- Все 83 команды из тематических групп имеют отдельное описание в меню. Старые текстовые команды и алиасы сохранены для совместимости; в стандартной справке остаются `.menu` и `.chelp`.
- Некоторые сложные игровые сценарии (например, создание квеста и управление наградами) используют собственные интерактивные мастера. Прямые банковские и служебные операции запускают исходные callback-функции из форм меню.

Подробное руководство: `GUIDES.md`.

## Система квестов: два типа награды

При создании квеста или квеста из шаблона укажите поле `Награда: алмазы, XP`:

- `100, 50` — после подтверждения выполнения участнику полагается 100 алмазов и 50 XP.
- `0, 0` — квест без предметной награды; существующий бонус к зарплате в процентах всё равно начисляется.
- Можно указать `0` для одной из наград, если нужна только другая.

Для ручных квестов доступны периодичности `daily` (ежедневный), `weekly` (еженедельный) и `once` (единоразовый — публикуется один раз и не повторяется по расписанию). Режим (`individual` / `group`) выбирается отдельно. Шаблоны для автоматической публикации остаются ежедневными или еженедельными. Пользовательские шаблоны принимают поле `Категория | алмазы, XP`, например `📋 Свои | 100, 50`. Для изменения награды любого шаблона откройте `.menu` → «Управление квестами» → «Шаблоны и награды» → «Настроить награду». Старую команду `.template_reward ID АЛМАЗЫ XP` также можно использовать; `0 0` отключает предметную награду. Автоматические квесты используют награды, сохранённые в шаблонах.

Бот не может физически передать алмазы или опыт в Minecraft. После подтверждения квеста награда помечается ожидающей выдачи; после фактической передачи глава соответствующей гильдии открывает `.menu` → «Управление квестами» → «Выдать награду» и выбирает участника. Старую команду `.quest_reward_paid ID Ник` также можно использовать. Дата и автор подтверждения сохраняются, повторная отметка не допускается. Старые квесты без полей награды автоматически трактуются как квесты без дополнительной награды, но с прежним процентным бонусом к зарплате.

## Файлы данных

- `guild_data.json`, `quest_templates.json`, `quest_schedule_config.json` — существующие данные RPG-бота.
- `creditors.json`, `loans.json` — реестр кредитного отдела и кредиты.
- `bank_accounts.json` — накопительные счета.
- `bank_deposits.json` — срочные вклады.
- `treasury.json` — казна, резерв, сотрудники банка и незавершённые расходы.

Новые JSON-файлы создаются автоматически при первой записи. Повреждённые банковские файлы не должны автоматически перезаписываться пустыми данными.

## Справка по командам

- `.chelp` или `.помощь` — открыть ролевую справку по командам.
- `.menu`, `.меню` или `.панель` — открыть интерактивное меню.
- В справке есть краткие инструкции по созданию квестов с наградой и без неё, управлению шаблонами, отметке фактической выдачи награды и расписанию автоквестов.
- Команды для глав гильдий и администраторов показываются в отдельных разделах в зависимости от роли.

## Служебные отчёты СОБР

- `.sobr_report` / `.собр_отчёт` — открыть форму создания отчёта. Доступ: ранг СОБР D и выше. Выберите тип: правонарушение, инвентаризация ресурсов, проверка паспортов или прочий служебный отчёт.
- В форме укажите основание и цель, участников/проверяемых лиц, содержание и при необходимости время выполнения в формате `ДД.ММ.ГГГГ ЧЧ:ММ` (московское время). Если время оставить пустым, используется текущее время МСК.
- В отчёте об инвентаризации укажите в содержании `Здание: название` и `Ресурсы: алмазы=10, железо=20`. Следующий отчёт по тому же зданию сравнит количества с последней инвентаризацией; положительная разница означает прирост, отрицательная — уменьшение. Уменьшение само по себе не доказывает нарушение.
- `.sobr_reports [ожидает]` — последние отчёты или отчёты, ожидающие подтверждения (ранг D+).
- `.sobr_dossier [@игрок]` — личное дело; доступно только участникам СОБР, чужое дело — сотрудникам ранга B и выше. Каждый отчёт добавляется в дела всех указанных участников/проверяемых лиц.
- `.sobr_violation_confirm ID [решение]` — подтвердить правонарушение после рассмотрения (ранг B+). До подтверждения запись не увеличивает счётчик нарушений.
- За каждые два подтверждённых нарушения создаётся отдельный штраф на 200 алмазов. `.sobr_fines [@игрок]` показывает штрафы, `.sobr_fine_paid @игрок ID [примечание]` фиксирует погашение только после физической передачи алмазов в Minecraft. Бот не переводит алмазы.
- `.sobr_report_correct ID текст` — добавить исправление отдельной записью; исходный отчёт не переписывается.
- `.sobr_passport_report` — вручную сформировать недельный отчёт (ранг B+). Автоматический отчёт публикуется по понедельникам в 10:00 МСК в закрытом канале. В нём перечислены все зарегистрированные игроки на конец завершившейся недели и отдельно показаны проверки паспортов, зарегистрированные за эту неделю.
- Команды СОБР доступны только участникам СОБР (по регистрации или ролям ранга); создание отчётов и исправлений требует ранга D+, подтверждение нарушений/штрафов и ручной отчёт о паспортах — B+. Администратор Discord сохраняет обход прав.
- В `.chelp` раздел СОБР отображается только сотрудникам СОБР и администраторам. Раздел служебных команд банка/кредитного отдела отображается участникам Торговцев.
- При первом запуске бот пытается создать закрытый канал `закрытые-отчёты-собр` в категории СОБР. Доступ на чтение и публикацию предоставляется рангам D, C, B, A, S и главе СОБР; администраторам Discord доступен обход ограничений канала.
- Данные системы хранятся в `sobr_reports.json`; проверки паспортов берутся из `creditors.json`, регистрация — из `guild_data.json`.

## Регистрация без гильдии

Игрок может написать боту в личные сообщения команду `.register`, затем отправить ник Minecraft и подтвердить регистрацию реакцией ✅. Команда `.cancel_registration` отменяет незавершённую регистрацию. Такой профиль сохраняется отдельно от гильдий; позже игрок может вступить в гильдию, отправив действующий код приглашения в ЛС бота.

### Обновления системы квестов

- ID теперь создаётся до публикации и показывается прямо в записи форумной доски, в сообщении об успешном создании и в меню «Управление квестами» → «Список квестов и ID».
- Список ID показывает последние 25 квестов выбранной гильдии (администратор видит все гильдии) и карточку с типом, статусом, режимом, бонусом и ссылкой на публикацию.
- Меню «Выдать награду» учитывает ожидающие награды у разовых, ежедневных и еженедельных квестов; тип квеста также отображается в списке и подтверждении выдачи.
- Разовые квесты, созданные вручную или из шаблона, используют общий механизм подтверждения и ожидания предметной награды.
- При ручном закрытии квеста все ещё выполняющиеся заявки переводятся в состояние «отменён», поэтому глава не сможет случайно подтвердить уже закрытый квест. Просроченное индивидуальное выполнение теперь сразу получает соответствующий статус и штраф, даже если фоновая проверка ещё не успела сработать.
- Созданный квест сохраняется в JSON до добавления реакций. Если Discord не позволит добавить одну из реакций, запись квеста не потеряется и его ID останется доступен.
